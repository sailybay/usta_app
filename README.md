# Usta App 🛠️
**Платформа для поиска мастеров и предоставления бытовых услуг**

Usta App — это кроссплатформенное мобильное приложение на базе **Flutter**, разработанное в рамках дипломного проекта. Приложение объединяет клиентов, которым необходимы бытовые услуги (ремонт, клининг, сантехника и т.д.), и мастеров, готовых эти услуги предоставить.

## 🌟 Ключевые возможности (Функционал)

### Для клиентов (Client Floor):
*   **Умный поиск:** Каталог услуг с фильтрацией по категориям и сортировкой по цене или рейтингу потоков.
*   **Карта (OpenStreetMap):** Интеграция бесплатной карты для выбора адреса предоставления услуги. Установка геометок (`lat/lng`).
*   **Биржа заказов:** Возможность создания публичного заказа, на который могут откликнуться мастера.
*   **AI Ассистент (Groq API):** Интеграция умного помощника, помогающего в описании проблемы, расчетах и поддержке.
*   **Система отзывов:** Оценка работы мастера после завершения заказа (5-звездная рейтинговая система).

### Для мастеров (Worker Floor):
*   **Панель управления (Dashboard):** Персональный дашборд с аналитикой доходов и списком активных услуг.
*   **Управление услугами:** Добавление новых услуг `CRUD` с установкой цен, прайс-листа и описания навыков.
*   **Поиск работы (Order Finder):** Возможность просматривать заявки клиентов и принимать их в работу («Биржа»).
*   **Чат реального времени:** Общение с клиентами в реальном времени прикрепленное к каждому заказу.

## 🏗 Архитектура проекта

Проект спроектирован по паттерну **Clean Architecture** (Роберт Мартин), что гарантирует низкую связность компонентов и простоту тестирования.

В проекте 3 основных слоя:
1.  **Data Layer** (`/lib/data`): Работа с внешними источниками. API, интеграция SDK Firebase (`auth`, `firestore`). Имплементация интерфейсов. Содержит строгие `Models` для конвертации JSON.
2.  **Domain Layer** (`/lib/domain`): Ядро бизнес-логики. Не зависит ни от каких библиотек Фреймворка! Содержит Абстрактные Репозитории (Interfaces) и `Entities` (Сущности).
3.  **Presentation Layer** (`/lib/presentation`): Графический интерфейс на Flutter. Разделен на экраны (`screens`), компоненты (`widgets`) и стейт-менеджмент (`blocs`). Навигация контролируется библиотекой `GoRouter`.

**Управление состоянием (State Management):**
Используется **BLoC** (Business Logic Component). Отдельные BLoC классы написаны для: Auth, Service, Orders, Localizations, AI и профилей Мастеров.

## 🚀 Оптимизация и Производительность

В рамках разработки была проведена глубокая оптимизация производительности (Performance & Memory Tune-up):
*   **Stream-архитектура в Firebase:** База работает только через слушателей реального времени. Вместо сотен `HTTP GET` запросов, Firebase отдает один сокет по каналу `snapshots()`, экономя до 70% трафика и расхода аккумулятора приложения.
*   **Сборка мусора (Garbage Collection):** Переведено использование устаревших методов анимаций в `Color.withValues(...)` для предотвращения утечек GPU памяти.
*   **Навигация (Shell Routing):** Интеграция ShellNavigation позволила держать интерфейс нижних вкладок в кэше без перестроения дерева `build()`, что обеспечивает **стабильные 60 FPS**.

## 🏁 Как запустить проект

**Требования:**
- Стабильный `Flutter SDK 3.19.x` или выше.
- Подготовленная среда (Android Studio, Xcode).

**Шаги запуска:**
1. Клонируйте репозиторий на локальную машину:
   ```bash
   git clone <repository_url>
   ```
2. Откройте директорию приложения и установите все зависимости:
   ```bash
   cd usta_app
   flutter pub get
   ```
3. Для генерации кэша (если менялись переводы `l10n`):
   ```bash
   flutter gen-l10n
   ```
4. Запустите тесты, чтобы убедиться в работоспособности бизнес-логики:
   ```bash
   flutter test
   ```
5. Запустите приложение на устройстве или эмуляторе:
   ```bash
   flutter run
   ```
